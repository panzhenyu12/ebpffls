# 自适应行为检测开发计划

> 2026-09-07；状态：P0 首批增量已实现并通过 Docker 验证，P0 尚未整体完成。依据 [竞品研究复核](./ebpf-ml-security-research.md) 和当前工作区源码。本文保留目标设计，不代表所有接口、配置、指标已实现或实测；首批实现边界见 [Event ABI v2](./event-abi.md)。P0/P1/P2/P3 表示开发顺序。

## 目标与边界

面向保护 Linux 容器、文件服务及 AI 工作负载的运维/安全人员：既识别无已知后缀、慢速、多进程拆分的破坏行为，又能解释为什么备份、编辑器、数据库和模型 checkpoint 不应被同一组全局阈值误伤。

“不死板”定义为：同一操作数量能根据顺序、对象、时间分布、进程关系和 workload 基线产生不同判断；不要求命中唯一固定序列，也不把高资源使用、加密库调用或模型异常分数单独等同恶意。

保留现有 IOC/hash/自保护及有效动作约束；新增分析首先 shadow（记录判定但不执行）。第一阶段不做完整 EDR、容器全局自动隔离、在线自训练深度网络、内容熵分析或真实恶意样本执行。后续挖矿检测是独立可选 profile，不拖延勒索行为检测。

## 融合方式

| 借鉴来源 | 本项目落点 | 不照搬的部分 |
|----------|------------|--------------|
| PATROL 上下文 profile、策略/执行分离 | 进程实例 + workload 身份，证据与动作仲裁 | 命令名称即恶意；未验证的同步能力与容器隔离保证 |
| ebpfangel 峰值/累计/三元序列 | 成功操作比例、速率、短语义序列频次，与同文件关联结合 | 未关联文件的固定 O/C/E/D pattern；OpenSSL 作为必要条件 |
| CryptoGuard 分层检测、响应前核验 | 精确低成本摘要、定向详细观察、独立证据交叉验证 | 默认引入 CMS；按 comm 追踪/终止；触发后补造此前序列 |
| Tetragon 序列与容器 metadata | 顺序敏感特征、容器聚合、简单模型对照和严格数据切分 | 全 syscall LSTM 默认常开；把已知应用分类当未知威胁检测 |

目标数据流：

```text
受策略约束的内核确定性快路径 ----------------------> 原有强制执行 + 审计
                    |
                    v
归一化事件 -> 进程/文件/workload 上下文 -> 有界多窗口特征
                                               |
                         规则 / 时序 / 基线 / 可选模型
                                               |
                                         Evidence 集合
                                               |
                                  去重、交叉验证、动作仲裁
                                      |              |
                              采集升级请求      能力检查与执行
```

新证据层不等待模型再放行同步 IOC；用户态异步分析只能影响判定后的操作，不能承诺追回已完成写入。

## 数据与模块设计

### 1. 事件和身份先可靠

- 版本化 BPF wire ABI，新增 syscall/source、attempt/success/blocked、result、单调时间与关联序号。写请求字节数、实际成功字节数、writev 向量数分字段，不把未知填成 0。跨 CPU 乱序以有界重排处理，迟到/缺失单列质量状态。
- 用成功 exec 事件（优先 `sched_process_exec`）更新已执行身份；attempt 只提供行为证据。补 fork/exec-success/exit 生命周期、FD 继承/dup/close 与失败 close 语义，不能由失败 exec 获得可信路径身份。
- `ProcessKey = (boot_id, host_tgid, start_time)`；父关系也绑定实例，维护有限深度 lineage。内核 blocked map 的实例校验与退出清理一并设计，不能只修用户态而保留 PID 重用误伤。
- hash/模型异步任务和结果同时绑定进程实例与可执行对象身份；排队后退出、再次 exec 或证据过期的结果应丢弃。用户态终止用 pidfd 或同等实例绑定机制，最终执行前确认目标；不能只用 `os.FindProcess(TGID)` 发信号。旧内核缺乏强身份能力时，不执行依赖该证明的新增自动强制，并明确降级。
- 事件带 cgroup ID，结合 namespace、容器/部署 metadata 做归属；workload 基线键需跨进程重启稳定、跨租户隔离，并区分镜像/版本。metadata 异步补充，不能在关键事件上等待远端服务。未知归属单独标记，不猜测同租户。
- 文件身份优先 mount namespace + device/inode 等可验证对象键，并保留路径用于保护域解释；路径解析不可靠时降低关联质量。inode/FD 重用、rename、硬链接和文件生命周期要测试，拿不到对象身份的 legacy 路径仅提供路径级弱证据。
- 将 `bpf/events.h`、三套 `ransomware*.bpf.c`、`internal/sensor/event.go`、reader 和生成对象作为同一契约修改。旧传感器字段缺失明确记 unknown，不由 Go 层伪造成功/字节数。

### 2. 特征先于分数

将归一化、生命周期更新和有界统计放在评分之前；不把所有原始日志无界保存。现有 trusted 豁免默认兼容，但新增 shadow 统计保留其低成本上下文。以后提供显式的“上下文信任”模式，仅作为有上限的先验，不吞掉备份破坏、自保护等证据。

第一批特征：

| 特征组 | 内容 | 解决的问题 |
|--------|------|------------|
| 文件修改 | 成功修改的 distinct files/dirs、现有文件成功写入、截断比例、创建后替换/删除比例 | 可写 open 不等于写入；同路径次数不等于影响文件数 |
| 时间分布 | 多时间窗速率、峰值/均值、短长窗比、扩散持续时间 | 突发攻击、低速跨窗口行为和周期正常任务 |
| 顺序 | 同对象的 open -> write、write -> rename、create/write -> replace/unlink；2/3-gram 与转移频率 | 相同数量不同顺序、临时文件替换与批量破坏的区别 |
| 上下文 | 可执行身份、父子关系、workload/version、保护域、备份路径、正常外联变化 | 多进程拆分和不同业务的行为差异 |
| 数据质量 | 能力、事件丢失/抽样率、乱序、归属与文件解析质量、窗口是否完整 | 不把缺失数据当正常，也不把抽样邻接当真实邻接 |

建议起始观察尺度为 1 秒桶、10 秒/60 秒/5 分钟窗口，全部有容量上限；这是待回放校准的实验起点，不是已验证默认值。低速行为必须在长窗聚合，但不强迫快速 IOC 等待长窗结束。

现有事件没有 read 成功字节，不声明已经识别 read -> encrypt 链。需要时在 elevated 模式加受预算约束的 read/pread/readv 与加密库弱信号，另行验证收益。mmap/io_uring 的弱观察与确认修改分开。

写入字节数也不足以区分追加与覆盖。首批不承诺覆盖比例；该特征需额外采集偏移、append/position 语义及此前文件范围，并测试 seek/pwrite、稀疏文件与并发写入，缺失时为 unknown。旧 `open_write_pairs` 保留兼容含义，新增真实配对使用不同特征名，不能悄悄改变旧规则阈值的含义。

### 3. 可组合行为，不是另一套固定字符串

新增用户态行为检测器，第一批是批量现有文件修改、批量替换删除、备份破坏与后续文件扩散、多进程共同扩散。规则支持受限 all/any、scope、within、次数/比例约束和允许噪声的顺序条件；可选步骤、未观察到的步骤和失败尝试有不同含义。

例如“多个文件成功写入 + 与本 workload 基线相比异常扩散 + 可疑替换/备份破坏上下文”形成复合证据；rename/已知后缀不是必要步骤。正常编辑器也会 write -> rename，因此单链只给弱证据，需结合对象范围、重复模式与 workload 基线。多个低速子进程在同 workload 聚合，但动作只落到证据明确绑定的进程实例。

限制规则深度、窗口数、活跃对象数和最大状态数；编译时拒绝不支持字段、矛盾时间窗与无界状态。先实现有需求的组合，不引入通用脚本执行或任意查询语言。

### 4. Evidence 与决策

以下为拟议内部契约，不是当前 API：

```text
Evidence: detector/version, scope/instance, observed_interval, reasons,
          features, strength, quality, expires_at, correlated_group
Decision: evidence_ids, requested_action, effective_action, target_instance,
          policy_version, capability, execution_status, failure_reason
```

各检测器均产出证据，不直接操作 blocked map。异常值/模型分数不是天然概率；未校准就标为 score，不展示“恶意概率 99%”。对同一文件事件派生的 fanout、速率和 n-gram 设相关分组与贡献上限，避免一份证据重复加权。

| 证据状态 | 新增自适应检测默认行为 |
|----------|----------------------|
| 单一基线偏离或模型异常 | 记录与定向升级观察，不 kill，不自动修改白名单 |
| 多种独立行为证据相互印证 | shadow 给出候选动作；通过评估且显式启用后，按策略允许的动作执行 |
| 已有确定性 IOC/hash 等命中 | 保留现有策略快路径，不受低置信模型否定；不自动扩大其作用域 |
| 关键数据丢失/身份未知 | 输出 degraded/unknown，限制基于缺失字段的推论，保留不依赖它们的快路径 |

新引擎收集全部匹配证据后一次仲裁；log 不能抑制同作用域已获策略授权的强制动作。deny 和 kill 不是可以任意互换的置信等级：dry-run 永不执行，缺少 deny 能力不自动升级 kill。动作请求、map 下发、实际拒绝/终止确认分别记录，不把 kill 请求成功写成进程已退出。

向后兼容：旧 `rules[]`、分数、trust 行为默认不暗改。新增引擎先显式 opt-in/shadow；提供旧 first-match 与新合并判定的差异日志及迁移说明，再决定默认切换。新语法仅进入设计/测试夹具，不能直接加入现有生产 YAML；当前 `KnownFields(true)` 会拒绝未知字段。

现有 alert/metrics 的 `schema_version:v1` 字段含义保持不变；新增证据事件单独版本化，语义不兼容的特征或告警升级 schema 并提供迁移说明。wire ABI 版本与外部 JSON schema 版本分别管理。

### 5. Workload 基线

先用有界历史的中位数/MAD 或分位数对速率/比例做稳健偏离检测，回放选定一种实现后固定版本；漂移监测可以使用 EWMA，不同时堆叠多种算法。明确最小样本量、MAD 为零、空闲期、冷启动和版本更新策略。

基线仅从准入的干净运行/观察窗更新；可疑或丢失窗口冻结，不因异常持续足够久就自动变“正常”。保留版本、来源、样本量和回滚；新 workload 进入 unknown，不能套用另一租户的基线。发布变化触发重新观察或人工确认，不能自动生成可执行白名单。

### 6. 有预算的升级采集

状态为 normal -> elevated -> cooldown -> normal；进入/退出阈值分开，设置最短驻留、TTL、最大并发 scope、每 scope 与全局事件/内存预算。优先在内核维护廉价摘要、选择性输出，否则只在 Go 丢弃事件不能降低内核和传输成本。

常态保留 lifecycle、FD 关联和关键 IOC 审计，并留有界触发前摘要/短缓冲。升级只增加后续详细数据，不声称恢复此前未采集的完整序列。抽样中断显式标记，不能跨缺口生成连续 n-gram；压力下紧急丢失也必须可见，不自动豁免 workload。超时/重启撤销采集升级 map，不留下永久全量采集。

### 7. 轻量模型与可选挖矿 Profile

先离线比较现有规则、规则+时序、再加基线、再加逻辑回归/小决策树或 n-gram 分类器，按同一隔离测试集做消融。只有在增量召回或提前量确有提升且误报/开销受控时才接入用户态 shadow。序列词表、架构映射、预处理、特征 schema、模型和阈值一起版本化，训练/推理输入必须逐项一致。

首版不在线更新模型、不将推理放入 LSM/kprobe、不允许模型单独 kill。模型缺失、超时、异常输出或 schema 不兼容时回退确定性规则，并报告降级。

挖矿 profile 后续组合 CPU/scheduling 时间、syscall 动态、网络目的地/流量与持久化上下文；这些新增信号需单独采集实现。正常 AI 训练/推理、编译、压缩、科学计算必须进良性集；高 CPU、GPU 活动或加密库调用本身不应触发强制。

### 评估方法与候选 Gate

先按完整运行实例拆分，再生成窗口；关联 fork 树和同一源样本的衍生运行归同一组。分别保留未见家族/行为变体与未见正常 workload 的测试集。词表、scaler、基线、模型只在训练数据拟合，阈值只在验证集选择，测试集不反复调参。数据集规模不够时只报告场景回归，不能宣传家族泛化。

以下是待 AD-00 建立基线后确认的工程验收目标，不是当前实测结果或生产 SLA：

- 正确性：已有确定性快路径与 dry-run 用例全部通过；新增身份/失败 syscall/仲裁用例全部通过；所有 skip 和能力缺口单列。
- 增量检测：无后缀、慢速、多进程三类各至少 20 次独立模拟运行，逐类报告召回和分母；目标各 >=95%，同时通过对应良性对照。模拟高分不代表真实恶意样本召回。
- 误报：发布前 shadow 至少覆盖 500 workload-hours 和上述主要正常类别，候选告警观测率目标 <=1/100 workload-hours，候选错误强制为 0。预先固定同 workload/同原因告警的 incident 去重窗口，同时报告原始事件数与去重后次数；报告样本量、工作负载构成和置信区间，不能宣称生产零误报。若以 Poisson 单侧 95% 上界作为额外 Gate，零误报也需约 300 小时才能使上界达到 1/100；需注明独立/平稳假设，不能用大量重复窗口代替独立暴露。
- 效果：逐场景报告从首个已标注恶意操作到首次告警/实际阻断的 p50/p95/p99，以及阻断前确认受影响文件数。分位数标明是已检出子集及样本数；未检测运行在截止时计为 miss/右删失，另报全体运行截至各时间点的召回，不能把子集分位数称为总体时延。小样本 p99 只作描述，不作稳定性能承诺。模拟器用文件校验确认影响，不拿 write 请求量当损坏量。
- 时延：现有 IOC 的相同环境 p95/p99 不显著退化；同步路径候选回归预算为 10%，超过则暂停放量排查。语义检测按快速/慢速场景独立设预算，不把 5 分钟观察窗当快速响应承诺。
- 成本：常态相对当前 agent 的业务吞吐/延迟额外退化目标 <=5%；elevated 每 scope/全局内存和事件预算可断言。至少同时报告无 agent、旧 agent、新 normal、新 elevated 四组，记录硬件/内核/负载和重复次数。
- 模型：在相同数据拆分与误报预算下，相对规则+时序+基线必须有稳定增量召回或检测提前量，否则不合入在线模型。

发布顺序：回放 -> Docker/专用 LSM 环境 -> shadow -> 显式启用低风险 scope -> 扩大范围。每阶段保存策略/特征/基线/模型版本与上一版包；撤销新引擎后恢复旧检测器并清理其采集状态。shadow 不产生新的强制 map 写入。
